# Security posture — Claude Code Manager 1.0.0

Reviewed 2026-07-27 against the shipped `--onedir` build. This document states what
was checked and what was **not**. Where a claim could not be fully verified, it says so.

## What the application does

A Tkinter launcher. It has three effects on the system:

| Effect | Detail |
|---|---|
| Reads/writes one file | `%APPDATA%\ClaudeCodeManager\config.json` — two keys: `current_dir`, `terminal` |
| Creates directories | Only under a parent the user picks in the folder dialog (`+ New Project`) |
| Spawns a console | `powershell.exe` or `cmd.exe` in a new console, `cd`'d to the selected project, running `claude` |

It does **not** write to the registry, install a service, request elevation, create
startup/persistence entries, or modify anything outside the paths above.

**Network:** no source file imports `socket`, `ssl`, `urllib`, `http`, `requests`, or
`asyncio` (verified by grep across `main.py` and `src/`), and there is no code path
that opens a connection. However, `_socket.pyd` and `_hashlib.pyd` **are** present in
`dist\ClaudeCodeManager\_internal` — PyInstaller's dependency analysis pulls them in via
the Tcl/Tk runtime hook despite the `excludes` in `ClaudeCodeManager.spec`. So the correct
statement is *the application makes no network calls*, not *the bundle is incapable of
networking*. A reviewer scanning imports of the frozen bundle will see those two
extensions; that is expected and not evidence of network behaviour.

## Artifact integrity

Verify before running. Build `1.0.0` (post launcher hardening):

```
8ADF1A76D9BF6F202C18E1232CF698A43D45CCAA592475BDC626FE67DE2BF053  ClaudeCodeManager.exe
```

```powershell
Get-FileHash .\dist\ClaudeCodeManager\ClaudeCodeManager.exe -Algorithm SHA256
```

`dist\SHA256SUMS.txt` is regenerated by `build.ps1` on every build. If you rebuild,
the hash changes — a rebuild is not bit-for-bit reproducible (PyInstaller embeds
build-time paths).

## Code signing — the open gap

**This build is unsigned.** Consequences, stated plainly:

- Users launching it on a machine that has not seen it before get
  **"Windows protected your PC — Unknown publisher"** from SmartScreen. They must click
  *More info → Run anyway*. This is expected, not a malfunction.
- AppLocker/WDAC **publisher rules cannot be used** — there is no signature to bind to.
  Path or hash rules against the install directory are the only options. For `--onedir`,
  a path rule must cover the whole `ClaudeCodeManager\` folder, since the exe loads
  `python313.dll` and `_internal\*` from beside itself.
- EDR products score unsigned PyInstaller binaries more aggressively. Mitigations
  already applied: a full version resource (`version_info.txt`), `upx=False` (packed
  sections are a standard heuristic), and `--onedir` so nothing self-extracts into
  `%TEMP%` at runtime.

To sign, uncomment the block in `build.ps1`:

```powershell
signtool sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 `
    /a dist\ClaudeCodeManager\ClaudeCodeManager.exe
```

Use an RFC-3161 timestamp (`/tr`, not the deprecated `/t`) so signatures outlive the
certificate. Sign only `ClaudeCodeManager.exe`; the bundled CPython DLLs are already
Microsoft/PSF-signed.

**Unsigned means unverified publisher.** This build is enterprise-*ready* in metadata,
filesystem hygiene, and input handling. It is not enterprise-*deployable* until signed.
No code change closes that gap.

## Findings addressed in this build

### Fixed — unqualified interpreter names were hijackable

`subprocess.Popen` with a bare `"powershell.exe"` calls `CreateProcess` with
`lpApplicationName = NULL`, whose search order includes **the calling process's
directory and the CWD before `System32`**. A `powershell.exe` dropped beside
`ClaudeCodeManager.exe` — trivial in an unzipped `Downloads` folder — would have been
executed in preference to the real shell.

`src/launcher.py` now resolves `argv[0]` from `%SystemRoot%\System32` and falls back
to the bare name only if that absolute path is absent. Enforced by
`test_powershell_argv0_is_absolute_system32` and `test_cmd_argv0_is_absolute_system32`.

### Fixed — apostrophes in paths broke out of the PowerShell string

`C:\Ben's Code` is a legal NTFS path. Interpolated raw into
`Set-Location -LiteralPath '...'`, the apostrophe closed the quote and the remainder
of the path was parsed as PowerShell. Now escaped by doubling (`_ps_quote`),
PowerShell's own escape. Enforced by `test_powershell_escapes_apostrophe`.

### Verified safe — CMD path interpolation

`cd /d "{path}" && claude`. `"` cannot appear in an NTFS path, so the quote cannot be
closed from a path; `&`, `|`, `^` inside double quotes are not operators to `cmd.exe`.
No injection route found.

### Verified safe — config file as a trust boundary

`config.json` is user-writable and hand-editable. `AppState.load()` type-checks both
keys and discards anything unexpected (`current_dir` must be a non-empty `str`,
`terminal` must be `powershell` or `cmd`), so garbage cannot reach `Path()` or the
launcher. `save()` swallows `OSError` — an unwritable config degrades to
non-persistence rather than crashing a click handler. Covered by
`test_load_rejects_garbage_values`, `test_load_survives_corrupt_file`,
`test_save_never_raises_on_unwritable_path`.

### Verified safe — folder-name validation

`validate_folder_name` in `src/ui.py` rejects path separators and `:*?"<>|`, `.`/`..`,
control characters, leading/trailing spaces, trailing dots, and the Windows reserved
device names (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`) including with an
extension (`nul.txt`). Input is a single folder name, never a path.

## Residual risk — accepted, not fixed

**`claude` resolves from the project directory in CMD mode.** The spawned shell runs
bare `claude` after `cd`-ing into the selected project, and `cmd.exe` searches the
**current directory first**. A `claude.bat` or `claude.exe` committed to a cloned
repository would run instead of the real CLI.

Not fixed deliberately: pinning an absolute `claude` path would break version managers,
npm-style shims, and the per-project wrappers users legitimately rely on.

Mitigations: **PowerShell mode is unaffected** — PowerShell does not resolve commands
from the CWD — and PowerShell is the default. Treat launching Claude Code in an
untrusted repository as equivalent to running any other tool there; the trust decision
belongs to whoever cloned it.

## Out of scope for this review

Not assessed, because the application has no such surface: authentication, session
management, transport security, server-side authorization, deserialization of
untrusted input (config is JSON parsed into two scalars), SQL/ORM access. The
OWASP Top 10 web categories do not map onto a local single-user desktop launcher.

Not assessed, though relevant if distribution widens: the supply-chain integrity of
the PyInstaller bootloader and the CPython 3.13.12 runtime that are bundled into
`dist\ClaudeCodeManager\_internal`.
